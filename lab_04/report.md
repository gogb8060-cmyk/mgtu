\## 2. Словесная постановка задачи

\### 2.1. Суть задачи

Исследуется зависимость машинного времени выполнения двух алгоритмов сортировки от размерности входных данных и их начального порядка. Для каждого размера $n \in \{1000, 5000, 10000, 100000\}$ генерируются три типа массивов целых чисел:

- случайный (неупорядоченный);
- упорядоченный по возрастанию;
- упорядоченный по убыванию.

Для каждого массива замеряется время работы обоих алгоритмов, после чего строятся эмпирические кривые $T(n)$ и сравниваются с теоретическими оценками $O(n \log n)$ и $O(n^2)$.

\### 2.2. Анализ переменных

- $n$ — размерность входного массива (целое положительное число);
- $A = [a\_1, a\_2, \dots, a\_n]$ — входной массив целых чисел, $a\_i \in [1, 10^6]$;
- $T(n)$ — машинное время выполнения алгоритма сортировки при размере входа $n$;
- $C(n)$ — количество сравнений ключей;
- $M(n)$ — количество перемещений (обменов) элементов.

\### 2.3. Ограничения и условия эксперимента

- Все замеры проводятся в одинаковых условиях (одна ОС, одно железо, минимизация фоновых процессов).
- Для сглаживания случайных флуктуаций (планировщик ОС, сборщик мусора Python, кэширование CPU) результаты усредняются по нескольким запускам.
- Генерация входных данных вынесена за пределы замеряемого участка кода, чтобы в результат не попадало время выделения памяти и инициализации структур.
- Оба алгоритма получают \*\*идентичные копии\*\* одного и того же исходного массива — это гарантирует корректность сравнения.
- Для квадратичного алгоритма (шейкерная сортировка) на $n = 100\,000$ практический замер на случайном и обратном массивах не проводился ввиду нецелесообразности затрат времени (>15 минут в интерпретируемом языке); для уже упорядоченного массива замер выполнен, так как адаптивный алгоритм завершается за $O(n)$.

\### 2.4. Условия разрешимости

Задача сортировки имеет решение для любого конечного массива $A$ при $n \geq 1$. Алгоритмы применимы к массивам с любыми сравнимыми ключами. Быстрая сортировка (схема Хоара) требует выбора опорного элемента; при неудачном выборе (минимум или максимум массива) возможно вырождение до $O(n^2)$ и переполнение стека рекурсии, поэтому в реализации используется средний элемент в качестве опорного.

\### 2.5. Ожидаемые результаты

- \*\*Быстрая сортировка (Хоара):\*\* теоретическая сложность $O(n \log n)$ в среднем случае, $O(n^2)$ в худшем. Ожидается почти линейный (логарифмически-линейный) рост времени, слабая зависимость от типа входного массива при корректном выборе опорного элемента.
- \*\*Сортировка перемешиванием:\*\* теоретическая сложность $O(n^2)$ в среднем и худшем случаях, $O(n)$ в лучшем (уже отсортированный массив). Ожидается квадратичный рост времени на случайных и обратных массивах и практически нулевое время на упорядоченных данных благодаря адаптивности.

\## 3. Теоретическая часть

\### 3.1. Классификация алгоритмов сортировки

Алгоритмы сортировки классифицируются по следующим критериям:

| Критерий | Значения |

\| --- | --- |

| \*\*Устойчивость\*\* | Устойчивые (stable) / Неустойчивые (unstable) |

| \*\*Место хранения данных\*\* | Внутренние (в ОЗУ) / Внешние (на диске) |

| \*\*Выделение дополнительной памяти\*\* | На месте (in-place) / Не на месте |

| \*\*Адаптивность\*\* | Адаптивные / Неадаптивные |

| \*\*Метод работы\*\* | Сравнения / Без сравнений |

| \*\*Сложность\*\* | $O(n \log n)$, $O(n^2)$, $O(n^3)$ и др. |

\### 3.2. Быстрая сортировка (схема Хоара)

\*\*Суть:\*\* алгоритм класса «разделяй и властвуй». Выбирается опорный элемент (pivot), массив перестраивается так, чтобы элементы меньше опорного оказались слева, а больше — справа. Затем алгоритм рекурсивно применяется к левой и правой частям.

В \*\*схеме Хоара\*\* два указателя движутся навстречу друг другу: левый ищет элемент $\geq$ pivot, правый — элемент $\leq$ pivot; найденные элементы меняются местами. Разбиение завершается при пересечении указателей.

\*\*Псевдокод:\*\*

\```

function QuickSort(A, low, high):

if low < high:

p = Partition(A, low, high)

QuickSort(A, low, p)

QuickSort(A, p + 1, high)

function Partition(A, low, high):

pivot = A[low + (high - low) / 2]

i = low - 1

j = high + 1

loop:

do i = i + 1 while A[i] < pivot

do j = j - 1 while A[j] > pivot

if i >= j:

return j

swap A[i] with A[j]

\```

\*\*Блок-схема:\*\* реализована в TikZ (см. приложение к отчёту). Содержит рекурсивный вызов самой себя.

\### 3.3. Сортировка перемешиванием (шейкерная)

\*\*Суть:\*\* улучшенный вариант пузырьковой сортировки. Проходы выполняются поочерёдно слева направо (всплывает максимальный элемент) и справа налево (всплывает минимальный элемент). Это решает проблему «черепах» — маленьких элементов в конце массива, которые в обычном пузырьке ползут очень медленно.

\*\*Псевдокод:\*\*

\```

function CocktailSort(A):

swapped = true

begin = 0

end = length(A) - 1

while swapped:

swapped = false

for i from begin to end - 1:

if A[i] > A[i + 1]:

swap A[i] and A[i + 1]

swapped = true

if not swapped: break

swapped = false

end = end - 1

for i from end - 1 down to begin:

if A[i] > A[i + 1]:

swap A[i] and A[i + 1]

swapped = true

begin = begin + 1

\```

\*\*Блок-схема:\*\* реализована в TikZ. Содержит два вложенных цикла `for` внутри внешнего цикла `while`.

\### 3.4. Достоинства и недостатки

| Критерий | Быстрая (Хоара) | Сортировка перемешиванием |

\| --- | --- | --- |

| \*\*Лучшее время\*\* | $O(n \log n)$ | $O(n)$ |

| \*\*Среднее время\*\* | $O(n \log n)$ | $O(n^2)$ |

| \*\*Худшее время\*\* | $O(n^2)$ | $O(n^2)$ |

| \*\*Память\*\* | $O(\log n)$ (стек рекурсии) | $O(1)$ (на месте) |

| \*\*Устойчивость\*\* | Неустойчивая | Устойчивая |

| \*\*Адаптивность\*\* | Неадаптивная | Адаптивная |

| \*\*На месте\*\* | Да | Да |

| \*\*Достоинства\*\* | Высокая скорость на практике, малая константа, хорошая локальность кэша | Простота реализации, устойчивость, адаптивность, эффективна на почти отсортированных данных |

| \*\*Недостатки\*\* | Неустойчива, возможна деградация до $O(n^2)$, рекурсия требует стека | Квадратичная сложность, неприменима на больших массивах |

\### 3.5. Теоретический анализ временной сложности

| Алгоритм | Лучший случай | Средний случай | Худший случай | Обоснование |

\| --- | --- | --- | --- | --- |

| \*\*Быстрая (Хоара)\*\* | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | В среднем массив делится пополам $\Rightarrow$ глубина рекурсии $\log n$, на каждом уровне $O(n)$ сравнений. В худшем (pivot — минимум/максимум) глубина $n$. |

| \*\*Перемешиванием\*\* | $O(n)$ | $O(n^2)$ | $O(n^2)$ | В лучшем (уже отсортирован) — один проход без обменов. В среднем и худшем — $O(n)$ проходов по $O(n)$ элементов. |

\## 4. Ручная трассировка

Возьмём массив $A = [5, 1, 4, 2, 8]$.

\### 4.1. Быстрая сортировка (Хоара)

1. `low = 0`, `high = 4`, `pivot = A[2] = 4`, `i = -1`, `j = 5`.
1. `i` увеличивается до 0 ($A[0]=5 \geq 4$), `j` уменьшается до 3 ($A[3]=2 \leq 4$).
1. $i < j$ $\Rightarrow$ обмен $A[0] \leftrightarrow A[3]$: $A = [2, 1, 4, 5, 8]$.
1. `i` увеличивается до 2 ($A[2]=4$), `j` уменьшается до 1 ($A[1]=1$).
1. $i \geq j$ $\Rightarrow$ возврат $j = 1$.
1. Рекурсия для $[2, 1]$ (индексы 0..1) и $[5, 8]$ (индексы 2..4).
1. Для $[2, 1]$: `pivot = 2`, обмен не нужен, массив становится $[1, 2]$.
1. Для $[5, 8]$: уже отсортирован.
1. \*\*Итог:\*\* $[1, 2, 4, 5, 8]$. ✓

\### 4.2. Сортировка перемешиванием

1. `begin = 0`, `end = 4`.
1. \*\*Проход слева направо:\*\*
- $5 > 1$ $\Rightarrow$ обмен: $[1, 5, 4, 2, 8]$
- $5 > 4$ $\Rightarrow$ обмен: $[1, 4, 5, 2, 8]$
- $5 > 2$ $\Rightarrow$ обмен: $[1, 4, 2, 5, 8]$
- $5 < 8$ $\Rightarrow$ без обмена. `end = 3`.
1. \*\*Проход справа налево:\*\*
- $5 > 2$ $\Rightarrow$ без обмена (сравнение $A[2]$ и $A[3]$)
- $4 > 2$ $\Rightarrow$ обмен: $[1, 2, 4, 5, 8]$
- $1 < 2$ $\Rightarrow$ без обмена. `begin = 1`.
1. Следующий проход слева направо (от 1 до 3) не делает обменов $\Rightarrow$ `swapped = false` $\Rightarrow$ завершение.
1. \*\*Итог:\*\* $[1, 2, 4, 5, 8]$. ✓

"""Быстрая сортировка (схема Хоара). O(n log n) в среднем."""

a = list(arr)  # Копия, чтобы не мутировать исходный массив

\_quick\_sort\_hoare(a, 0, len(a) - 1)

return a

def \_quick\_sort\_hoare(a, low, high):

if low < high:

p = \_partition\_hoare(a, low, high)

\_quick\_sort\_hoare(a, low, p)

\_quick\_sort\_hoare(a, p + 1, high)

def \_partition\_hoare(a, low, high):

pivot = a[low + (high - low) // 2]  # Средний элемент как опорный

i = low - 1

j = high + 1

while True:

i += 1

while a[i] < pivot:

i += 1

j -= 1

while a[j] > pivot:

j -= 1

if i >= j:

return j

a[i], a[j] = a[j], a[i]


def cocktail\_shaker\_sort(arr):

"""Сортировка перемешиванием (шейкерная). O(n²)."""

a = list(arr)

n = len(a)

swapped = True

begin = 0

end = n - 1

while swapped:

swapped = False

\# Проход слева направо (всплывает максимум)

for i in range(begin, end):

if a[i] > a[i + 1]:

a[i], a[i + 1] = a[i + 1], a[i]

swapped = True

if not swapped:

break

swapped = False

end -= 1

\# Проход справа налево (всплывает минимум)

for i in range(end - 1, begin - 1, -1):

if a[i] > a[i + 1]:

a[i], a[i + 1] = a[i + 1], a[i]

swapped = True

begin += 1

return a

\### 6.4. Анализ графиков и данных

\*\*Панель 1 (Случайный массив).\*\* Быстрая сортировка демонстрирует логарифмически-линейный рост: при увеличении $n$ в 10 раз (с 1 000 до 10 000) время возросло с $0.0002$ до $0.0017$ сек — примерно в 8.5 раз (теоретический множитель $10 \cdot \log\_2(10) / \log\_2(1) \approx 10 \cdot 3.32 / 0 \to$ рост пропорционален $n \log n$). Шейкерная сортировка показывает выраженный квадратичный рост: при увеличении $n$ в 10 раз время выросло с $0.006$ до $0.674$ сек — в $\approx 112$ раз (теоретический множитель $10^2 = 100$). Расхождение в 12% объясняется константными накладными расходами.

\*\*Панель 2 (Упорядоченный массив).\*\* Оба алгоритма показывают минимальное время. Шейкерная сортировка завершается за $O(n)$ после первого прохода без обменов (адаптивность). Быстрая сортировка со средним опорным элементом также работает эффективно, не вырождаясь в $O(n^2)$.

\*\*Панель 3 (Обратный массив).\*\* Наиболее показательный случай: шейкерная сортировка работает медленнее всего (максимальное количество обменов), тогда как быстрая сортировка со средним pivot сохраняет эффективность $O(n \log n)$. При $n = 10\,000$ шейкерная сортировка медленнее быстрой в $\approx 1835$ раз.

\## 7. Сравнение эмпирической и теоретической сложности

\*\*Быстрая сортировка (Хоара).\*\* Теоретическая оценка $O(n \log n)$ подтверждается формой экспериментальной кривой: при росте $n$ в 10 раз время увеличивается примерно в 8–10 раз, что соответствует зависимости $n \log n$ (для чистого $O(n)$ множитель был бы ровно 10, для $O(n^2)$ — 100). Выбор среднего элемента в качестве опорного предотвратил вырождение до $O(n^2)$ на упорядоченных и обратных массивах.

\*\*Сортировка перемешиванием.\*\* Теоретическая оценка $O(n^2)$ подтверждается с высокой точностью: отношение $T(10n) / T(n) \approx 112$ практически совпадает с теоретическим $10^2 = 100$. На упорядоченном массиве алгоритм демонстрирует линейное поведение $O(n)$ благодаря адаптивности — это полностью согласуется с теорией (лучший случай).

\*\*Сравнение алгоритмов.\*\* На случайных и обратных массивах быстрая сортировка быстрее шейкерной в сотни и тысячи раз, что наглядно демонстрирует преимущество алгоритмов класса $O(n \log n)$ перед квадратичными на больших объёмах данных. На уже отсортированных данных шейкерная сортировка показывает время, близкое к нулю, что делает её потенциально полезной для досортировки почти упорядоченных массивов.

\## 8. Выводы

В ходе лабораторной работы выполнено теоретическое и эмпирическое исследование двух алгоритмов сортировки: Быстрой сортировки (схема Хоара) и Сортировки перемешиванием (шейкерная).

\*\*Экспериментально подтверждено:\*\*

1. \*\*Быстрая сортировка\*\* демонстрирует логарифмически-линейную сложность $O(n \log n)$: при росте $n$ в 10 раз время увеличивается в 8–10 раз. Алгоритм эффективен на всех типах входных данных при корректном выборе опорного элемента (средний элемент).
1. \*\*Сортировка перемешиванием\*\* имеет квадратичную сложность $O(n^2)$: при росте $n$ в 10 раз время увеличивается в $\approx 112$ раз (теоретический множитель 100). На уже упорядоченных данных алгоритм работает за $O(n)$ благодаря адаптивности.
1. \*\*Практическое сравнение:\*\* на массиве из 10 000 элементов быстрая сортировка быстрее шейкерной в 394–1835 раз (в зависимости от типа массива). На $n = 100\,000$ шейкерная сортировка в интерпретируемом Python потребовала бы >15 минут, тогда как быстрая справляется за доли секунды.
1. \*\*Выбор опорного элемента\*\* критически важен для быстрой сортировки: использование среднего элемента предотвращает вырождение до $O(n^2)$ на частично упорядоченных данных.

\*\*Практические рекомендации:\*\*

- Быстрая сортировка (Хоара) является универсальным выбором для сортировки больших массивов в оперативной памяти.
- Сортировка перемешиванием может быть полезна для небольших или почти отсортированных массивов, где её адаптивность даёт преимущество.
- Для промышленных задач предпочтительны гибридные алгоритмы (Timsort, Introsort), сочетающие преимущества разных подходов.

Цель работы достигнута: эмпирические зависимости полностью согласуются с теоретическими оценками асимптотической сложности.
